One of my goals this year has been to become a stronger machine learning engineer by building complete systems—not just training models. SurVax is the result of that effort.

SurVax is an end-to-end platform for predicting childhood vaccination follow-up needs and transforming those predictions into actionable outreach campaigns. Rather than stopping at a probability score, the system helps answer a more practical question:

> Given limited outreach capacity, which children should public health teams prioritize?

## The Motivation

Many vaccination programs operate under significant resource constraints. Community health workers cannot visit every household, making prioritization an important operational challenge.

Most machine learning projects focus on producing accurate predictions. In practice, however, predictions are only useful if they support better decision making.

SurVax was designed around that idea. The objective is not simply to estimate vaccination follow-up risk, but to produce outputs that can directly support planning and resource allocation.

## Project Architecture

The project consists of several components that together form a complete machine learning workflow:

* Configuration-driven model training
* Automated preprocessing using scikit-learn Pipelines
* Experiment tracking with MLflow
* Batch prediction
* FastAPI REST API
* Dockerized deployment
* Capacity-aware vaccination campaign planning
* Continuous Integration with GitHub Actions

The overall workflow looks like this:

```text
Vaccination Data
        ↓
 Feature Engineering
        ↓
 Model Training
        ↓
 Model Artifacts
        ↓
 Risk Prediction
        ↓
 Campaign Planning
        ↓
 Prioritized Outreach List
```

## Campaign Planning

One feature I particularly enjoyed building was the campaign planning module.

Instead of returning only a predicted probability, SurVax can generate a prioritized outreach campaign based on available capacity.

For example, if a district has capacity for 500 household visits, the system:

* predicts a risk score for every child,
* ranks children from highest to lowest predicted risk,
* selects the highest-priority children within the available capacity,
* assigns recommended outreach actions,
* generates a campaign summary for program managers.

This shifts the focus from prediction to operational decision support.

## Software Engineering Focus

I approached SurVax as both a machine learning and software engineering project.

Some of the engineering practices incorporated into the project include:

* modular package architecture,
* reusable preprocessing pipelines,
* feature contract validation,
* unit testing with pytest,
* containerization with Docker,
* experiment tracking using MLflow,
* automated testing through GitHub Actions,
* deployment of the API using Render.

Building these components was an opportunity to learn how production-oriented machine learning systems are structured beyond the modeling stage.

## Lessons Learned

Working on SurVax reinforced several ideas for me:

* Machine learning models are only one component of a larger system.
* Reproducibility and testing become increasingly important as projects grow.
* Clear interfaces between training, inference, and domain-specific logic make projects much easier to maintain.
* Operational workflows often provide more value than prediction alone.

## Looking Ahead

There are several directions I would like to explore in future iterations of the project, including:

* support for additional vaccination schedules,
* explainable predictions using SHAP,
* region-aware campaign optimization,
* interactive dashboards for campaign visualization,
* model registry integration and monitoring.

SurVax has been one of my favorite projects because it combines my interests in machine learning, software engineering, and public health. It has also been a great exercise in thinking beyond model performance and toward building tools that can support real-world decision making.
